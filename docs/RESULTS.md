# 검증 방법 및 결과

## 재현 명령

프로젝트 루트에서 C 컴파일러와 `make`를 사용합니다.

```sh
make test CFLAGS='-std=c11 -Wall -Wextra -Werror -fsanitize=address,undefined'
make
./read_asm first.s
./read_asm examples/baseline.s
hexdump -C first.bin
hexdump -C baseline.bin
```

단위 테스트를 실행하고 두 입력의 전체 바이트를 대조했습니다. 전체 프로그램 빌드에는 `main.c`의 `argc` 미사용 경고 한 건이 남아 있습니다. 오류 입력 테스트에서 나오는 진단은 예상한 결과이며, 테스트 성공 여부는 `make test`의 종료 상태로 확인합니다.

## 단위 테스트

| 항목                    | 확인한 결과                                                                                                                                                                                         |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 레지스터와 명령 테이블  | `x0`~`x31`, ABI 별칭, `fp=x8`, 잘못된 이름 `x32` 거부를 확인했습니다.                                                                                                                       |
| 줄 분리와 피연산자 매핑 | `lw t0, 4(sp)`의 분리 결과는 `[t0] [4(sp)]`이고, 매핑 결과는 `rd=5, rs1=2, imm=4`입니다. 따옴표 속 쉼표와 `#`가 문자열에 남는 것도 확인했습니다.                                            |
| 라벨                    | 전방 B형 분기는 `+8`, 후방 J형 점프는 `-12`로 매핑됐습니다. 미정의 라벨, 홀수 오프셋, 범위 초과 입력은 거부됐습니다.                                                                            |
| 인코더                  | 숫자 구조체를 직접 넣어 R/I/S/B/U/J형의 기대 워드와 비교했습니다. 문자열에서 파싱해 인코딩하는 경로도 별도로 검사했습니다.                                                                          |
| 지시어와 배치           | 섹션을 반복해서 선택했을 때 각 섹션의 위치가 이어지는지, `.equ`가 즉시값에 적용되는지, 절대 주소 기준 `.align`과 BSS 심볼 주소가 맞는지 확인했습니다.                                           |
| 가상 명령어와 CSR       | 가상 명령 23종, 한 피연산자 `jal`, 짧고 긴 `li`의 기대 워드를 검사했습니다. 32비트 범위를 벗어난 값, 없는 `la` 라벨, 홀수 분기 거리, 5비트 범위 초과 CSR 즉시값을 거부하는 것도 확인했습니다. |

인코더에 직접 피연산자를 넣은 결과입니다.

```text
인코더 sub | 0x406283B3
인코더 srai | 0x41F35293
인코더 sw | 0xFE712E23
인코더 beq | 0x00B501E3
인코더 lui | 0xFF2002B7
인코더 jal | 0xFF5FF0EF
```

## 파일 바이트 대조

`first.s`는 12바이트 `93 02 70 00 13 03 e0 f2 13 03 03 00`으로 변환됐습니다. `baseline.s`는 명령어 24바이트, 정렬 패딩 8바이트, 데이터 4바이트로 총 **36바이트**입니다. 아래 오프셋 `0x20`에서 데이터가 시작합니다.

```text
00000000  93 02 70 00 13 03 e0 ff  b3 83 62 00 63 84 73 00  |..p.......b.c.s.|
00000010  93 03 30 06 6f 00 00 00  00 00 00 00 00 00 00 00  |..0.o...........|
00000020  78 56 34 12                                       |xV4.|
00000024
```

## 실행 검증

CPUlator 웹사이트에 직접 접속해 RISC-V DE10-Lite 시스템에서 `baseline.bin`을 실행했습니다. Memory의 **Load/Save Memory**에서 파일 형식을 **Raw**로 고르고 시작 주소를 `0x00010000`으로 지정했습니다. 

| 항목        | 관찰값                            |
| ----------- | --------------------------------- |
| `t2`      | `0x00000005`                    |
| PC          | `0x00010014`의 `done` 루프    |
| 데이터 워드 | `0x00010020`에서 `0x12345678` |

CPUlator의 Raw 로드 절차와 기대 레지스터 값은 [README](../README.md#실행)에 있습니다.

## 가상 명령어 통합 검증

다음 입력을 임시 폴더의 `pseudo-check.s`로 저장한 뒤 어셈블했습니다. 소스 끝의 `.equ`를 앞에서 참조하고, 짧은 `li`와 긴 `li`가 연속해서 나온 뒤 `la`가 전방 데이터 라벨을 참조합니다. `beqz`로 한 명령을 건너뛰고 `call`로 진입한 함수가 `ret`으로 복귀합니다.

```asm
.text
li t0, SMALL
li t1, 2048
la t2, data
lw a0, 0(t2)
beqz zero, call_test
li a0, 0
call_test:
call increment
done:
j done
increment:
add a0, a0, t0
ret
.data
data: .word 5
.equ SMALL, 7
```

결과 파일은 52바이트입니다. 전체 13워드를 계산한 기대값과 바이트 단위로 대조했습니다.

```text
00700293 00001337 80030313 00000397 02438393 0003A503 00000463
00000513 008000EF 0000006F 00550533 00008067 00000005
```

CPUlator에서 같은 방식으로 `pseudo-check.bin` 52바이트를 `0x00010000`에 적재하고 **Step Into**를 열 번 눌렀습니다. `a0=0x0000000c`였고, `t2=0x00010030`이 가리키는 데이터 워드는 5였습니다. 함수가 복귀한 뒤 `ra`와 PC는 모두 `0x00010024`였습니다. 이 값으로 데이터 참조, 분기, 함수 호출 및 복귀를 확인했습니다.

## 배포 예제 진행 상태

처음 배포본과 `examples/expanded/` 사본을 어셈블했을 때의 결과입니다.

| 예제 | 바이너리 생성 결과                                         |
| ---- | ---------------------------------------------------------- |
| 1    | 44행 `li t0, (1 << IRQ_TIMER) \| (1 << IRQ_KEY)`에서 중단 |
| 2    | 원본과 사본 모두 796바이트 생성, 전체 바이트 일치          |
| 3    | 194행 `li t1, SCREEN_H * 512 / 4`에서 중단               |
| 4    | 34행 `li t0, 1 << IRQ_TIMER`에서 중단                    |

현재 값 파서는 정수, 문자 리터럴과 단일 심볼을 읽습니다. 표에 나온 산술식은 적용할 연산을 해석해야 하므로 오류가 납니다. 예제 2번은 파일 생성과 사본 일치까지 확인했고, CPUlator의 주변장치 동작과 제출용 동영상은 확인하지 못했습니다. 작업 폴더의 실습 입력 `실습/swtask.asm`은 68바이트로 변환됐습니다.

이후 각 예제에서 처음 실패했던 산술식을 상수로 바꾼 작업 폴더의 입력을 재검증했습니다. 3번은 884바이트를 생성했고, 1번은 67행, 4번은 66행의 다음 산술식에서 멈췄습니다. 나머지 치환과 임시 복사본의 변환 결과는 [배포 예제의 산술식과 mret](PROCESS.md#배포-예제의-산술식과-mret)에 있습니다.
