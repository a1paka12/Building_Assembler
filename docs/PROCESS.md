# 구현 과정 및 오류 수정 기록

이 프로젝트에서는 직접 코드와 구조를 수정하고, 막히는 지점은 AI에 질문하면서 진행했습니다. 파일 읽기와 인자 처리, 파서 구조, 테이블 위치를 직접 검토하고 수정했습니다. 바이너리 변환 코드, 레지스터·명령·지시어 테이블 초안, 유닛 테스트 코드 작성에는 AI의 도움을 받았습니다. 가상 명령어 구현과 일부 코드 수정도 AI에 요청했고, 여러 컴파일,링크 오류는 제가 오류 메시지를 읽고 함수 선언과 정의를 확인해 직접 수정했습니다.

작업 단계별 질문은 [AI 사용 범위와 재구성 프롬프트](AI_PROMPTS.md)에 정리했습니다.

## 구현 순서

1. **한 명령을 바이너리로 쓰기.** `fgets()`로 입력 한 줄을 읽고 `addi`의 피연산자를 분리했습니다. 32비트 워드를 만든 뒤, 하위 바이트부터 4바이트를 파일에 썼습니다.
2. **문자열 분리와 명령 해석을 나누기.** 포맷별로 파서 파일을 나눈 구성을 정리해 `parse.c`에 모았습니다. `parse_line()`은 주석을 제거하고 라벨, 명령 이름, 피연산자 문자열을 분리합니다. `parse_instruction()`은 명령 테이블을 조회해 레지스터·즉시값을 포맷에 맞는 `union` 멤버에 저장합니다.
3. **라벨과 실제 명령 포맷 연결.** 시작 주소 `0x10000`을 기준으로 라벨 주소를 수집한 뒤, B/J형에서 `목표 주소 - 현재 PC`를 계산했습니다. 여섯 포맷을 `encode.c`에 연결해 테이블의 `opcode`, `funct3`, `funct7`과 피연산자 비트를 합쳤습니다.
4. **섹션과 지시어 연결.** `layout.c`는 상수와 각 섹션의 크기·주소를 계산합니다. `directives.c`는 지시어의 크기를 계산하고 데이터 바이트를 생성합니다. `values.c`는 숫자·문자·이스케이프를 명령어와 지시어에서 공통으로 해석합니다.
5. **예제 범위 조정.** 처음에는 배포 원본을 `examples/`에 두고, `examples/expanded/` 사본에서 비교 분기 가상 명령 네 종류와 `csrs`를 동작이 같은 실제 명령으로 펼쳤습니다. 사본 네 개에서 총 14줄을 치환했습니다.
6. **가상 명령 확장.** 배치 단계에서 4바이트 또는 8바이트를 예약하고, 출력 단계에서 실제 명령으로 확장해 기존 인코더에 넘겼습니다.

## 소스가 바이너리가 되는 과정

| 단계           | 하는 일                                                                                                                                                                            |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 줄 분리        | 따옴표 밖의 `#`만 주석으로 처리하고, 쉼표로 피연산자를 나눕니다. 예를 들어 `lw t0, 4(sp)`에서 `4(sp)`는 한 토큰으로 남습니다.                                                |
| 배치           | `.equ` 상수를 먼저 모으고 `.text`, `.data`, `.bss`의 시작 주소와 크기를 구합니다. 절대 주소에 맞춘 `.align`을 계산하기 위해 배치 단계에서 입력을 섹션별로 다시 읽습니다. |
| 매핑           | 명령 이름으로 포맷을 찾고 `t0 → x5`처럼 레지스터를 번호로 바꿉니다. `4(sp)`는 오프셋 4와 베이스 레지스터 x2로 해석합니다. 라벨 분기와 점프는 PC 상대 오프셋을 구합니다.       |
| 가상 명령 확장 | 가상 명령을 실제 명령 한 개 또는 두 개로 바꿉니다. 확장된 명령 수가 배치에서 계산한 크기와 맞는지 확인합니다.                                                                      |
| 인코딩         | 선택된 포맷의 비트 배치에 따라 32비트 워드를 구성합니다. S/B/J형은 즉시값의 조각을 각 위치에 배치합니다.                                                                           |
| 파일 출력      | `.text` 뒤에 16바이트 정렬 패딩과 `.data`를 씁니다. `.bss`는 메모리 주소와 크기만 차지합니다. 오류 없이 처리가 끝나면 임시 파일을 최종 `.bin` 이름으로 바꿉니다.           |

예를 들어 `addi t0, zero, 7`은 `rd=5`, `rs1=0`, `imm=7`로 해석됩니다. 조립된 워드는 `0x00700293`이고, 파일에서는 `93 02 70 00` 순서로 저장됩니다.

## 파서와 테이블 설계

줄 분리 단계는 `lw t0, 4(sp) # comment`를 명령 이름 `lw`와 두 토큰 `t0`, `4(sp)`로 나눕니다. 이어지는 매핑 단계에서 I형 로드의 opcode를 조회하고, 두 번째 토큰을 오프셋 `4`와 베이스 레지스터 `sp`로 나눕니다. 최종 `IformatOperands`에는 `rd=5`, `rs1=2`, `imm=4`가 들어갑니다. 명령 이름과 숫자 변환을 분리해, 어느 단계에서 값이 잘못됐는지 테스트에서 바로 확인할 수 있습니다.

- `register_table.h`는 `x0`부터 `x31` 순으로 ABI 별칭을 저장합니다. 배열에서 찾은 인덱스가 레지스터 번호입니다. 예를 들어 `t3`를 찾으면 28번이고, `fp`는 `s0`와 같은 8번입니다.
- `instruction_table.h`는 각 명령의 이름, 포맷, opcode, funct3, funct7과 고정 워드를 담습니다. 인코더는 선택된 명령의 메타데이터를 받아 워드를 만듭니다. 현재 파서는 등록된 이름의 문법과 지원 상태도 확인합니다.
- `directive_table.h`는 지시어 이름을 `enum DirectiveKind`에 연결합니다. `.globl`과 `.global`은 같은 종류로 처리합니다.
- `operands.h`는 포맷별 피연산자 구조체를 두고, `ParsedInstruction`의 포맷과 `union`을 통해 어느 멤버가 채워졌는지 구분합니다.

## 라벨과 섹션 주소 계산

라벨이 있는 줄을 만날 때 현재 섹션의 위치를 라벨에 붙입니다. 라벨만 있는 줄은 위치를 소비하지 않습니다. `baseline.s`의 분기 명령은 `0x1000C`에 있고, `done`은 `0x10014`에 있습니다. 따라서 오프셋은 `0x10014 - 0x1000C = 8`입니다. 뒤에 나오는 라벨을 찾을 수 있도록 주소 수집을 끝낸 뒤 명령을 인코딩합니다.

| 섹션      | 주소와 출력                                                                                                                 |
| --------- | --------------------------------------------------------------------------------------------------------------------------- |
| `.text` | `0x10000`부터 배치합니다. 실제 명령 하나는 4바이트입니다.                                                                 |
| `.data` | 텍스트 끝을 다음 16바이트 경계로 올린 위치에서 시작합니다. 텍스트와 데이터 사이의 패딩은 0입니다.                           |
| `.bss`  | 데이터 끝을 16바이트 경계로 올린 위치에서 시작합니다. 저장할 공간의 주소와 크기를 계산하며 파일 길이에는 포함되지 않습니다. |

배치 단계에서는 `.equ`를 먼저 수집하고, 텍스트의 끝을 구한 후 데이터의 시작을, 데이터의 끝을 구한 후 BSS의 시작을 확정합니다. 그래서 `.data`의 `.align 5`는 섹션 내부 오프셋에 32바이트를 기계적으로 적용하는 방식 대신, 실제 주소를 32바이트 경계에 맞춥니다. 두 출력 경로가 같은 크기 규칙을 사용하도록 `layout_line()`에서 한 줄의 크기를 계산합니다.

`.word`는 정수나 심볼 주소를 4바이트로 저장합니다. `.byte`와 `.half`는 각각 1바이트와 2바이트를 쓰며, 홀수 주소의 `.half`는 오류로 처리합니다. `.ascii`와 `.asciz`는 이스케이프를 처리한 뒤 길이를 계산하고, `.asciz`는 문자열 뒤에 0을 하나 더 씁니다. 예를 들어 `.asciz "a\n"`은 `61 0a 00`입니다.

## 가상 명령어의 길이와 확장

`pseudo_table.h`는 치환할 명령 이름과 피연산자 배치를 담습니다. 예를 들어 `bgt t0, t1, end`는 두 비교 레지스터의 순서를 바꾼 `blt t1, t0, end`가 됩니다. `mv t0, t1`은 끝에 즉시값 0을 붙인 `addi t0, t1, 0`이 됩니다. 확장 결과를 `parse_instruction()`에 넘겨 분기 범위와 레지스터 번호를 같은 규칙으로 확인합니다.

| 종류                                   | 배치와 인코딩                                                                                                                                          |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `li rd, imm`                         | 즉시값이 `-2048..2047`이면 `addi rd, x0, imm` 한 개를 씁니다. 그 밖의 32비트 값은 `lui`와 `addi` 두 개로 나눕니다.                             |
| `la rd, label`                       | 첫 명령의 PC를 대상 주소에서 뺀 값을 `auipc`와 `addi`로 나눕니다.                                                                                  |
| `call label`, `jal label`, `ret` | 단일 피연산자 호출은 `jal ra, label`로 확장합니다. `ret`은 `jalr x0, 0(ra)`입니다. 따라서 호출 거리는 J형 범위를 따릅니다.                       |
| 비교와 CSR 별칭                        | 비교는 조건에 맞춰 피연산자를 바꾸거나 x0을 추가합니다. CSR 별칭은 CSR 번호를 I형의 12비트 위치에, 레지스터 번호나 5비트 즉시값을 rs1 위치에 넣습니다. |

`li t0, 2048`의 하위 12비트는 `0x800`이고, `addi`에서는 `-2048`을 뜻합니다. 상위 값을 1로 보정해 `lui`가 4096을 만들고 `addi`가 2048을 빼도록 합니다. `la`도 PC 상대 차이에 같은 분할 규칙을 적용합니다. 상수는 배치 전 읽고, 주소 라벨은 `0x10000` 이상이므로 앞·뒤에서 참조해도 짧은 `li`로 잘못 분류되지 않습니다.

## 인코딩 예시

| 입력                 | 변환 근거                                                 | 출력 워드      |
| -------------------- | --------------------------------------------------------- | -------------- |
| `addi t0, zero, 7` | `imm=7`을 31:20, `rd=5`를 11:7, opcode를 6:0에 배치   | `0x00700293` |
| `add t2, t0, t1`   | `rd=7`, `rs1=5`, `rs2=6`과 R형 opcode를 합침        | `0x006283B3` |
| `sw t2, -4(sp)`    | 하위 12비트 `0xFFC`를 S형의 상위·하위 필드에 나눔      | `0xFE712E23` |
| `beq t2, t2, done` | 현재 명령에서 목표까지 8바이트를 B형의 분산된 필드에 배치 | `0x00738463` |

음수 즉시값은 부호가 있는 정수로 검증한 다음, 인코딩에 필요한 하위 비트만 뽑습니다. B/J형은 짝수 오프셋을 요구합니다. S형의 저장 오프셋은 12비트 부호 있는 값이므로 `sb t0, 1(sp)`처럼 홀수도 인코딩할 수 있습니다.

### 배포 예제의 산술식과 `mret`

예제 1번 44행, 3번 194행, 4번 34행에서 `'li'의 레지스터 또는 값이 잘못됨`이 나왔습니다. 메시지가 두 피연산자 오류를 하나로 표시했지만, 세 줄의 첫 번째 피연산자인 `t0`와 `t1`은 유효했습니다. 두 번째 피연산자에는 시프트, 비트 OR, 곱셈, 나눗셈이 들어 있었습니다. 현재 값 파서는 숫자, 문자 리터럴과 단일 심볼을 읽으므로, 예제에서 식을 미리 계산한 상수로 치환하는 방법을 택했습니다.

| 예제·행  | 기존 코드                                    | 치환한 코드                  |
| --------- | -------------------------------------------- | ---------------------------- |
| 1번 44행  | `li t0, (1 << IRQ_TIMER) \| (1 << IRQ_KEY)` | `li t0, 0x00050000`        |
| 1번 67행  | `li t1, 0x80000000 \| IRQ_TIMER`            | `li t1, 0x80000010`        |
| 1번 69행  | `li t1, 0x80000000 \| IRQ_KEY`              | `li t1, 0x80000012`        |
| 1번 88행  | `mret`                                     | `.word 0x30200073  # mret` |
| 3번 194행 | `li t1, SCREEN_H * 512 / 4`                | `li t1, 15360`             |
| 4번 34행  | `li t0, 1 << IRQ_TIMER`                    | `li t0, 0x00010000`        |
| 4번 66행  | `li t1, 0x80000000 \| IRQ_TIMER`            | `li t1, 0x80000010`        |
| 4번 80행  | `mret`                                     | `.word 0x30200073  # mret` |
| 4번 414행 | `addi a0, a0, -'a' + 10`                   | `addi a0, a0, -87`         |

`IRQ_TIMER=16`, `IRQ_KEY=18`, `SCREEN_H=120`을 예제의 `.equ`에서 확인했습니다. `-'a' + 10`은 ASCII의 `'a'=97`을 대입해 `-87`로 계산했습니다. 산술식을 모두 치환하기 전에는 처리 순서에 따라 다음 식에서 차례로 멈췄습니다. 1·4번의 `mret`에서는 `지원하지 않는 명령 'mret'`이 나왔습니다. `.word`에 해당 명령의 기계어 `0x30200073`을 쓰면 같은 위치에 4바이트가 배치됩니다.

치환을 모두 적용한 임시 복사본은 1번 716바이트, 3번 884바이트, 4번 2,380바이트의 바이너리를 생성했습니다. 작업 폴더에 첫 오류 줄(1번 44행, 3번 194행, 4번 34행)이 반영된 시점에도 다시 변환했습니다. 3번은 884바이트를 생성했고, 1번은 67행, 4번은 66행의 다음 산술식에서 멈췄습니다. 이 확인은 바이너리 생성까지 진행했습니다.

이후 4번 66행에 `li t1, 0x80000010  # 0x80000000 | IRQ_TIMER`를 반영했습니다. `IRQ_TIMER`의 값 16은 16진수로 `0x10`이므로 `0x80000000`과 OR 하면 `0x80000010`이 됩니다. 재변환은 66행을 통과한 뒤 80행에서 `지원하지 않는 명령 'mret'`을 출력했습니다. 80행의 `mret`을 `.word 0x30200073  # mret`로 바꾸면, 그 자리에 인터럽트 복귀 명령의 바이트 `73 00 20 30`이 들어갑니다.

80행을 바꾼 뒤에는 414행의 `addi`까지 진행했고, `잘못된 즉시값 '-'a' + 10'`이 나왔습니다. 이 코드는 소문자 `a`부터 `f`까지를 10부터 15까지로 변환합니다. `addi a0, a0, -87`로 바꾸면 `a`는 `97 - 87 = 10`, `f`는 `102 - 87 = 15`가 됩니다. [예제 4번의 오류 재현 순서와 ChatGPT 화면](AI_PROMPTS.md#예제-4번을-한-줄씩-고치는-대화)

1번 핸들러에서는 `mcause`를 읽은 뒤 67행에서 타이머, 69행에서 키 인터럽트 원인과 비교합니다. `0x80000000`에 타이머 번호 `0x10`과 키 번호 `0x12`를 각각 OR 한 결과가 `0x80000010`, `0x80000012`입니다. 이 두 값을 `li`에 넣고 기존 `beq`를 그대로 실행하도록 했습니다. 재변환은 두 줄을 통과한 뒤 88행에서 `지원하지 않는 명령 'mret'`을 출력했습니다. 임시 복사본에서 88행을 `.word 0x30200073  # mret`로 바꾼 뒤에는 716바이트가 생성됐습니다.

## 오류를 확인할 때 사용한 순서

1. `make`가 가리킨 파일과 줄에서 선언,정의,호출부의 함수 이름, 매개변수 타입, 반환 타입을 비교했습니다.
2. 링크 단계까지 간 오류에서는 정의가 들어 있는 `.c`가 빌드 목록에 들어 있는지, 다른 파일에서 호출할 함수에 `static`이 붙어 있는지 확인했습니다.
3. 폴더 구조를 바꾼 뒤에는 작은 입력 하나부터 실행하고, 파서 출력과 인코딩 워드를 각각 비교했습니다. 그 뒤 `hexdump`로 파일 오프셋과 바이트를 확인했습니다.
4. 파일까지 맞으면 CPUlator에 적재할 때 **Raw 형식, 메모리 시작 주소, PC**를 각각 확인했습니다. 시뮬레이터 관찰값은 [검증 결과](RESULTS.md)에 구분해 기록했습니다.
