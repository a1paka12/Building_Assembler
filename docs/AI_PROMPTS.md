# AI 사용 범위와 프롬프트

## 작업에서 AI를 사용한 범위

이 프로젝트에서는 직접 코드와 구조를 수정하고, 막히는 지점은 AI에 질문하면서 진행했습니다. 파일 읽기와 인자 처리, 파서 구조, 테이블 위치를 직접 검토하고 수정했습니다. 바이너리 변환 코드, 레지스터·명령·지시어 테이블 초안, 유닛 테스트 코드 작성에는 AI의 도움을 받았습니다. 가상 명령어 구현과 일부 코드 수정도 AI에 요청했고, 여러 컴파일,링크 오류는 제가 오류 메시지를 읽고 함수 선언과 정의를 확인해 직접 수정했습니다.

실제 구현 및 검증 결과는 [구현 과정](PROCESS.md)과 [검증 결과](RESULTS.md)에 기록했습니다.

## 1. 입력 파일과 첫 바이너리

> C로 과제 하려는데, 기계어로 만들라는 게 내가 프로그램 자체를 어셈블리로 짜라는 말인지 헷갈려. 입력 파일, 내가 만드는 프로그램, 결과 파일이 각각 뭔지 예시로 보여줘봐.
>
> 그럼 `./read_asm first.s`에서 파일 이름이 변수 어디로 들어와? 한 줄씩 읽으려면 `fgets`를 어떻게 써야 하는지 보여주고, 다음 줄을 읽으면 아까 나눈 문자열 포인터가 어떻게 되는지도 알려줘.
>
> `addi t0, zero, 7` 한 줄부터 해볼게. `0x00700293`을 왜 `93 02 70 00`으로 써야 돼? 바이트 배열 만드는 코드랑 `fwrite`, `hexdump`로 확인하는 것까지 알려줘봐.

## 2. 컴파일, 링크, 출력 경로

> C 파일을 나눴더니 `make`에서 함수 이름을 못 찾는다고 떠. 헤더에 선언이 있는데도 왜 그래? 선언이 틀린 경우, 정의에 `static`이 있는 경우, Makefile에서 `.c`가 빠진 경우를 로그 보고 어떻게 구분해?
>
> `argv[1]`에 `examples/demo.asm`이 들어올 때 결과는 현재 폴더의 `demo.bin`이면 돼. `strrchr`로 어디를 찾는 건지랑, 디렉터리랑 확장자가 없는 경우도 알려줘.
>
> `printf`를 넣었는데 정상일 때 아무것도 안 찍혀. 오류가 났을 때만 들어가는 분기인지 어디부터 보면 돼? 결과 파일이 만들어졌는지는 터미널에서 뭘로 확인해?

## 3. 파서, 레지스터, 명령 테이블

> `lw t0, 4(sp) # test`에서 일단 이름이랑 토큰만 나누고 싶어. 근데 `.asciz "a,#b"`는 쉼표랑 샵도 문자잖아. 주석 지우는 함수 따로 두면 따옴표는 어디서 확인해?
>
> `t0`, `sp`, `x5` 같은 게 들어오면 숫자로 저장하려고 해. ABI 별칭 표에서 인덱스가 실제 번호가 되는 이유랑 `s0`랑 `fp`가 같이 들어올 때 처리하는 법 알려줘.
>
> 명령 이름으로 포맷이랑 opcode, funct 값을 찾는 헤더 테이블 만들어줘. R형이랑 S형 피연산자 저장 순서가 다른데, `enum`하고 `union`을 써서 파싱 함수 안에서 어떻게 매핑해?

## 4. 라벨, 인코딩, 유닛 테스트

> `beq t0, t1, done`에서 `done`이 뒤에 나오면 지금은 숫자로 못 읽잖아. 파일을 두 번 읽어서 처음에는 뭘 저장하고 두 번째에는 PC에서 뭘 빼는지, 앞뒤 라벨 예시로 보여줘.
>
> `sw t2, -4(sp)`랑 뒤로 가는 `jal`은 즉시값 비트 순서가 헷갈려. S형의 12비트 범위하고 B/J형의 짝수 조건을 구분해서 워드 하나씩 계산해줘봐.
>
> 유닛 테스트 C 파일 하나로 파서랑 인코더 확인하게 코드 만들어줘. 파서에서 토큰이랑 레지스터 번호를 찍고, 인코더는 기대 워드를 직접 적어서 틀리면 실패하게 하고 싶어.

## 5. 지시어와 가상 명령

> `.word`랑 `.space`는 파일 크기가 어떻게 달라져? `.data` 섹션 시작 주소하고 `.align 5` 계산, `.bss`가 메모리만 차지하는 경우를 작은 주소 예시로 설명해줘.
>
> `li t0, 2048`은 왜 `lui` 하고 `addi -2048`이 나와? `la`는 어느 줄의 PC를 빼는지도 알려줘. 한 줄이 8바이트가 되면 뒤 라벨 주소는 언제 계산해야 돼?
>
> `mv`, `ret`, `bgt`, `csrr` 같은 건 테이블에서 바꿀 수 있을 것 같은데, 숫자 없이 이름만 다른 건 어떤 식으로 실제 명령 피연산자에 넣으면 돼? 기존 인코더를 재사용하고 싶어.

## 6. 파일과 실행 결과 대조

> `make test`가 통과하면 실제 파일까지 맞는지 어떻게 봐? 4바이트 워드를 손으로 계산해서 `hexdump`의 파일 오프셋이랑 한 줄씩 맞춰 보고 싶어.
>
> 바이너리를 메모리에 넣었는데 첫 바이트가 숫자 형식이 아니라고 떠. Raw 설정이랑 로드 주소랑 PC가 각각 뭔지 설명해줘. 실행하고 나서 레지스터랑 분기 주소 중 뭘 확인하면 돼?
>
> 작은 예제는 되는데 큰 예제 중 일부는 실패해. 첫 오류 줄에 있는 식이 문제인지 가상 명령 치환이 문제인지 어떻게 나눠서 확인해? 통과한 건 파일 생성 확인인지 시뮬레이터에서 실행 확인까지 한 건지도 구분해서 정리해줘.
